# 管理后台路由死循环问题修复方案

## 问题现象

部署到生产环境后，访问管理后台出现以下错误：

```
Uncaught RangeError: Maximum call stack size exceeded
    at index-D1m9tLtF.js:66:8409
    at Array.find (<anonymous>)
    at Object.c [as resolve] (index-D1m9tLtF.js:66:8396)
```

开发环境正常，但生产环境出现路由死循环，用户端正常，只有管理后台受影响。

## 问题根本原因

在 `admin-frontend/src/router/index.ts` 的路由守卫（`beforeEach`）中，存在会导致无限递归的逻辑：

### 问题代码位置：第191-208行

```typescript
// 如果已登录且有菜单数据，可能是路由还未添加，等待一下
if (adminStore.isLoggedIn() && adminStore.menus && adminStore.menus.length > 0) {
  // 检查是否需要添加路由
  const hasRoutes = router.getRoutes().some(r => {
    const routePath = r.path.startsWith('/') ? r.path : `/admin/${r.path}`
    return routePath === to.path || routePath === to.path + '/'
  })
  if (!hasRoutes) {
    console.log('路由未找到，尝试重新添加路由')
    // 重新添加路由（直接调用，避免循环依赖）
    addRoutes(adminStore.menus)
    // 等待路由添加完成后再检查
    await new Promise(resolve => setTimeout(resolve, 100))
    // 重新匹配路由 ⚠️ 这里会导致死循环！
    const retryMatched = router.resolve(to.path).matched.length > 0
    if (retryMatched) {
      console.log('路由添加成功，继续导航')
      next(to.path)  // ⚠️ 这里会再次触发 beforeEach，导致无限循环
      return
    }
  }
}
```

### 死循环的原因

1. **`router.resolve(to.path)` 在生产环境会触发路由守卫**：在压缩后的代码中，`router.resolve()` 会再次调用 `beforeEach`，形成递归
2. **`next(to.path)` 没有标记已尝试**：每次调用 `next(to.path)` 都会重新进入路由守卫，没有机制阻止重复尝试
3. **没有重试次数限制**：代码可以无限次地尝试添加路由和重定向

### 为什么开发环境没问题？

- 开发环境使用的是非压缩、非混淆的代码
- 生产环境的代码经过 Vite 构建，模块加载和路由解析的行为有所不同
- 生产环境的 `router.resolve()` 会触发更多内部逻辑

## 修复方案

### 方案1：使用标记防止重复尝试（推荐）

修改 `admin-frontend/src/router/index.ts` 第181-222行的路由守卫代码：

```typescript
// 调试日志：检查路由匹配情况
console.log('路由守卫 - 当前路径:', to.path, '匹配的路由:', to.matched.map(r => r.path), '路由名称:', to.name)

// 检查路由是否存在（排除404路由本身）
const matched = to.matched.length > 0
if (!matched && to.path.startsWith('/admin') && to.name !== 'admin-404' && to.name !== 'not-found') {
  // 路由不存在，尝试等待路由添加完成
  console.warn('路由未匹配，当前路径:', to.path, '已注册的路由:', router.getRoutes().filter(r => r.path.startsWith('/admin')).map(r => r.path))

  // 如果已登录且有菜单数据，可能是路由还未添加
  if (adminStore.isLoggedIn() && adminStore.menus && adminStore.menus.length > 0) {
    // 检查是否需要添加路由（只检查一次，避免循环）
    const hasRoutes = router.getRoutes().some(r => {
      const routePath = r.path.startsWith('/') ? r.path : `/admin/${r.path}`
      return routePath === to.path || routePath === to.path + '/'
    })

    // ✅ 新增：检查是否是第一次尝试（通过 query 参数标记）
    const isFirstAttempt = !to.query.__routeRetry

    if (!hasRoutes && isFirstAttempt) {
      console.log('路由未找到，尝试重新添加路由（仅尝试一次）')
      try {
        // 重新添加路由
        addRoutes(adminStore.menus)
        // ✅ 新增：标记已尝试，避免循环
        next({
          path: to.path,
          query: { ...to.query, __routeRetry: '1' },
          replace: true
        })
        return
      } catch (error) {
        console.error('添加路由失败:', error)
      }
    }
  }

  // 路由不存在或重试失败，根据登录状态重定向
  if (adminStore.isLoggedIn()) {
    // ✅ 新增：防止重定向到 dashboard 时再次进入这个逻辑
    if (to.path !== '/admin/dashboard') {
      ElMessage.warning('页面不存在，已跳转到首页')
      next('/admin/dashboard')
      return
    }
  } else {
    // ✅ 新增：防止重定向到 login 时再次进入这个逻辑
    if (to.path !== '/admin/login') {
      next('/admin/login')
      return
    }
  }
  // ✅ 新增：如果已经在目标页面，放行（避免循环）
  next()
  return
}
```

### 方案2：简化路由守卫逻辑（更简单但功能稍弱）

如果方案1还有问题，可以使用更简单的方式：

// 调试日志：检查路由匹配情况

## 其他可能的优化

### 1. 在应用初始化时就添加路由

修改 `admin-frontend/src/main.ts`，在路由初始化时就添加动态路由：

```typescript
import { createApp } from 'vue'
import { createPinia } from 'pinia'
import App from './App.vue'
import router, { addRoutes } from './router'
import { useAdminStore } from './stores/admin/user'
import ElementPlus from 'element-plus'
import 'element-plus/dist/index.css'

const app = createApp(App)
const pinia = createPinia()

app.use(pinia)
app.use(ElementPlus)

// ✅ 在挂载前初始化路由
const adminStore = useAdminStore()
if (adminStore.isLoggedIn() && adminStore.menus && adminStore.menus.length > 0) {
  console.log('应用启动时添加动态路由')
  addRoutes(adminStore.menus)
}

app.use(router)
app.mount('#app')
```

### 2. 配置正确的 base 路径

如果管理后台部署在子路径下（如 `https://example.com/admin/`），需要在 `vite.config.ts` 中配置：

```typescript
export default defineConfig({
  base: '/admin/', // ✅ 根据实际部署路径配置
  plugins: [vue()],
  // ...
})
```
