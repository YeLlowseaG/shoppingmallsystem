# 预存款冻结金额业务说明

## 当前状态

### 冻结金额和解冻金额字段
- **数据库字段**：`pre_deposit_detail` 表中有 `frozen_amount`（冻结金额）和 `unfrozen_amount`（解冻金额）字段
- **实体字段**：`PreDeposit` 实体中有 `frozenBalance`（冻结余额）字段
- **当前使用情况**：**所有业务逻辑中，这两个字段都设置为 `BigDecimal.ZERO`，目前未使用**

### 冻结金额的典型应用场景

冻结金额通常用于以下业务场景：

1. **订单支付时冻结资金**
   - 用户下单时，冻结订单金额
   - 防止用户同时支付多个订单导致余额不足
   - 订单支付成功后，解冻并扣减余额
   - 订单取消时，解冻资金

2. **退款时冻结资金**
   - 申请退款时，冻结退款金额
   - 等待退款审核
   - 退款通过后，解冻并扣减余额
   - 退款拒绝时，解冻资金

3. **提现时冻结资金**
   - 申请提现时，冻结提现金额
   - 等待提现审核
   - 提现通过后，解冻并扣减余额
   - 提现失败时，解冻资金

### 当前业务逻辑

**预存款支付（订单支付）：**
```java
// 直接扣减余额，没有冻结流程
preDeposit.setBalance(newBalance);
preDeposit.setAvailableBalance(newAvailableBalance);
```

**预存款退款：**
```java
// 直接增加余额，没有冻结流程
preDeposit.setBalance(newBalance);
preDeposit.setAvailableBalance(newAvailableBalance);
```

## 建议

### 方案1：保留字段，但隐藏显示（推荐）
- **优点**：为未来扩展预留空间，不影响现有业务
- **缺点**：前端页面需要隐藏冻结/解冻金额列
- **适用场景**：如果未来可能需要冻结功能（如订单支付、退款等）

### 方案2：移除字段
- **优点**：简化数据结构，减少混淆
- **缺点**：如果未来需要冻结功能，需要重新添加字段和业务逻辑
- **适用场景**：确定不需要冻结功能

### 方案3：实现冻结功能
- **优点**：完善业务逻辑，支持更复杂的资金管理
- **缺点**：需要修改现有业务逻辑，增加复杂度
- **适用场景**：需要支持订单支付冻结、退款冻结等场景

## 当前页面显示

预存款余额页面（`/member/deposit/balance`）目前显示：
- ✅ 存入金额
- ✅ 支出金额
- ⚠️ 冻结金额（当前所有记录都是0）
- ⚠️ 解冻金额（当前所有记录都是0）
- ✅ 当前余额
- ✅ 可用余额

## 建议操作

1. **如果不需要冻结功能**：
   - 隐藏前端页面的"冻结金额"和"解冻金额"列
   - 保留数据库字段和实体字段，但不显示

2. **如果需要冻结功能**：
   - 实现订单支付时的资金冻结逻辑
   - 实现退款时的资金冻结逻辑
   - 更新前端页面显示冻结/解冻金额

3. **如果不确定**：
   - 暂时隐藏前端页面的"冻结金额"和"解冻金额"列
   - 保留数据库字段和实体字段，等待业务需求明确后再实现
