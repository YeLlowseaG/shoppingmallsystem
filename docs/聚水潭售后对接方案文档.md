
# 聚水潭售后对接方案文档

## 一、方案概述

对接聚水潭ERP的订单取消接口和售后单上传接口，实现退款时自动同步到聚水潭。根据订单是否已发货，采用不同策略。

## 二、核心判断逻辑

### 2.1 发货前后判断标准

- **发货前**：`orderStatus == OrderStatus.PAID_UNSHIPPED`（值为 `1`，已付款未发货）
- **发货后**：`orderStatus == OrderStatus.SHIPPED`（值为 `2`，已发货）或 `OrderStatus.COMPLETED`（值为 `3`，已完成）

### 2.2 退款类型判断

- **部分退款**：`refundAmount < order.getTotalAmount()`（退款金额 < 订单商品总金额）
- **全额退款**：`refundAmount >= order.getTotalAmount()`（退款金额 >= 订单商品总金额）

## 三、场景处理方案

### 场景1：发货前部分退款

流程图：
```
退款操作 → 判断订单状态（PAID_UNSHIPPED） → 判断退款类型（部分退款）
    ↓
更新平台订单数据
    ↓
调用聚水潭订单上传接口（更新订单）
    ↓
标记退款商品明细（refund_qty、refund_status）
```

处理步骤：
1. 完成平台退款逻辑（更新订单、支付记录、退款记录等）
2. 判断订单已同步到聚水潭：`order.getErpSyncStatus() == 1`
3. 构建订单更新数据，在商品明细中标记退款商品：
   - `refund_qty`：退款数量（从 `OrderRefundItem.refundQuantity` 获取）
   - `refund_status`：设置为 `"success"`
   - 其他商品保持原样
4. 调用订单上传接口更新订单
5. 注意：`pay_amount` 和 `pay.amount` 保持原始金额，不扣减退款

### 场景2：发货前全额退款

流程图：
```
退款操作 → 判断订单状态（PAID_UNSHIPPED） → 判断退款类型（全额退款）
    ↓
更新平台订单数据
    ↓
检查是否已同步到聚水潭
    ↓
是 → 调用订单取消接口（使用o_id）
否 → 跳过（订单未推送，无需取消）
```

处理步骤：
1. 完成平台退款逻辑
2. 检查订单是否已同步到聚水潭：`order.getErpSyncStatus() == 1`
3. 检查是否有内部订单号：`order.getErpInternalOrderId() != null`
4. 调用订单取消接口：
   - 接口地址：
     - 正式：`https://openapi.jushuitan.com/open/jushuitan/orderbyoid/cancel`
     - 测试：`https://dev-api.jushuitan.com/open/jushuitan/orderbyoid/cancel`
   - 请求参数：
     - `o_ids`：`[Integer.parseInt(order.getErpInternalOrderId())]`
     - `cancel_type`：`"不需要了"` 或 `"全额退款"`
     - `remark`：退款原因（可选）
5. 处理接口响应，记录日志

重要说明：
- 订单取消接口仅支持特定状态的订单（待付款、发货中、异常、已付款待审核等）
- 如果订单状态不允许取消（如已发货），接口会返回错误，需要捕获并记录
- 此时可降级为上传售后单（场景3）

### 场景3：发货后退款（部分或全额）

流程图：
```
退款操作 → 判断订单状态（SHIPPED/COMPLETED） → 查询退款明细
    ↓
更新平台订单数据
    ↓
构建售后单数据
    ↓
调用售后单上传接口
```

处理步骤：
1. 完成平台退款逻辑
2. 查询退款记录和退款明细：`OrderRefund` 和 `OrderRefundItem`
3. 判断是否需要退货：
   - 仅退款：`type = "仅退款"`，`good_status = "BUYER_RECEIVED"`
   - 退货退款：`type = "普通退货"`，`good_status = "SELLER_RECEIVED"`（如有退货物流信息）
4. 构建售后单数据：
   - `shop_id`：从聚水潭配置获取
   - `outer_as_id`：`orderRefund.getRefundNo()`
   - `so_id`：`order.getOrderNo()`
   - `type`：售后类型
   - `shop_status`：`"SUCCESS"`
   - `good_status`：货物状态
   - `refund`：`orderRefund.getRefundAmount()`
   - `payment`：`0`
   - `items`：构建退款商品明细数组
     - `outer_oi_id`：`String.valueOf(orderItem.getId())`（订单项ID）
     - `sku_id`：商品SKU编码
     - `qty`：退款数量
     - `amount`：该SKU退款金额
     - `type`：明细类型（`"退货"` 或 `"其它"`）
5. 调用售后单上传接口：
   - 正式：`https://openapi.jushuitan.com/open/aftersale/upload`
   - 测试：`https://dev-api.jushuitan.com/open/aftersale/upload`
6. 处理接口响应，记录日志

## 四、技术实现要点

### 4.1 订单取消接口实现

需要新增方法：`JushuitanApiService.cancelOrderByInternalId(List<Integer> oIds, String cancelType, String remark)`

接口特点：
- 使用内部订单号（`o_id`），非订单号（`so_id`）
- `o_ids` 为数组，可批量取消
- 仅支持特定状态的订单

### 4.2 售后单上传接口实现

需要新增方法：`JushuitanApiService.uploadAftersale(JushuitanAftersaleDTO aftersaleDTO)`

需要新增DTO：`JushuitanAftersaleDTO` 及其内部类 `Item`

### 4.3 订单更新时退款商品标记

在 `JushuitanOrderDTO.Item` 中添加字段：
- `refund_qty`（Integer）：退款数量
- `refund_status`（String）：退款状态

### 4.4 数据映射关系

| 平台字段 | 聚水潭字段 | 说明 |
|---------|-----------|------|
| `Order.orderNo` | `so_id` | 订单号 |
| `Order.erpInternalOrderId` | `o_id` | 内部订单号（用于取消接口） |
| `OrderItem.id` | `outer_oi_id` | 订单明细编号（订单上传和售后单都需要） |
| `OrderRefund.refundNo` | `outer_as_id` | 售后单号 |
| `OrderItem.refundedQuantity` | `refund_qty` | 退款数量（订单更新时） |

### 4.5 错误处理

1. 订单取消接口错误：
   - 错误码 `130`：订单状态不允许取消
     - 处理：记录日志，可降级为售后单上传（如已发货）
   - 错误码 `120`：签名错误
     - 处理：检查签名算法
2. 售后单上传错误：
   - 检查 `outer_oi_id` 是否与订单上传时一致
   - 检查 `items` 类型是否正确
   - 记录详细错误信息用于排查

### 4.6 集成位置

在 `OrderServiceImpl.refundOrder()` 方法的最后，添加聚水潭同步逻辑：

```java
// 退款成功后，同步到聚水潭
try {
    syncRefundToJushuitan(order, refundNo, refundType);
} catch (Exception e) {
    // 记录日志，但不影响退款主流程
    log.error("退款同步到聚水潭失败: orderNo={}, refundNo={}", orderNo, refundNo, e);
}
```

## 五、实现伪代码

### 5.1 退款同步主入口

```java
private void syncRefundToJushuitan(Order order, String refundNo, Integer refundType) {
    // 1. 检查ERP是否启用
    if (!jushuitanApiService.isEnabled()) {
        log.warn("聚水潭未启用，跳过退款同步: orderNo={}", order.getOrderNo());
        return;
    }
    
    // 2. 判断是否已同步到聚水潭
    if (order.getErpSyncStatus() != 1) {
        log.warn("订单未同步到聚水潭，跳过退款同步: orderNo={}", order.getOrderNo());
        return;
    }
    
    // 3. 判断发货前后
    boolean isBeforeShipment = OrderStatus.PAID_UNSHIPPED.equals(order.getOrderStatus());
    boolean isFullRefund = RefundType.FULL_REFUND.equals(refundType);
    
    // 4. 根据不同场景处理
    if (isBeforeShipment) {
        // 发货前
        if (isFullRefund) {
            // 场景2：发货前全额退款 - 调用订单取消接口
            cancelOrderInJushuitan(order, refundNo);
        } else {
            // 场景1：发货前部分退款 - 更新订单标记退款商品
            updateOrderWithRefundItems(order, refundNo);
        }
    } else {
        // 场景3：发货后退款 - 上传售后单
        uploadAftersaleToJushuitan(order, refundNo);
    }
}
```

### 5.2 发货前全额退款 - 订单取消

```java
private void cancelOrderInJushuitan(Order order, String refundNo) {
    String erpInternalOrderId = order.getErpInternalOrderId();
    if (erpInternalOrderId == null || erpInternalOrderId.isEmpty()) {
        log.warn("订单无内部订单号，无法取消: orderNo={}", order.getOrderNo());
        return;
    }
    
    try {
        Integer oId = Integer.parseInt(erpInternalOrderId);
        jushuitanApiService.cancelOrderByInternalId(
            Arrays.asList(oId),
            "全额退款",
            "订单全额退款：" + refundNo
        );
        log.info("聚水潭订单取消成功: orderNo={}, oId={}", order.getOrderNo(), oId);
    } catch (NumberFormatException e) {
        log.error("内部订单号格式错误: orderNo={}, erpInternalOrderId={}", 
            order.getOrderNo(), erpInternalOrderId, e);
    } catch (Exception e) {
        log.error("聚水潭订单取消失败: orderNo={}", order.getOrderNo(), e);
        // 如果订单状态不允许取消，可以考虑降级为售后单上传
        if (e.getMessage().contains("不允许取消")) {
            log.info("订单状态不允许取消，降级为售后单上传: orderNo={}", order.getOrderNo());
            uploadAftersaleToJushuitan(order, refundNo);
        }
        throw e;
    }
}
```

### 5.3 发货前部分退款 - 更新订单

```java
private void updateOrderWithRefundItems(Order order, String refundNo) {
    // 查询退款明细
    List<OrderRefundItem> refundItems = getRefundItemsByRefundNo(refundNo);
    // 查询订单商品
    List<OrderItem> orderItems = getOrderItems(order.getId());
    
    // 构建订单更新数据
    JushuitanOrderDTO orderDTO = convertToJushuitanOrder(order, orderItems);
    
    // 标记退款商品
    Map<Long, OrderRefundItem> refundItemMap = refundItems.stream()
        .collect(Collectors.toMap(OrderRefundItem::getOrderItemId, item -> item));
    
    for (JushuitanOrderDTO.Item item : orderDTO.getItems()) {
        Long orderItemId = Long.parseLong(item.getOuterOiId());
        OrderRefundItem refundItem = refundItemMap.get(orderItemId);
        if (refundItem != null) {
            item.setRefundQty(refundItem.getRefundQuantity());
            item.setRefundStatus("success");
        }
    }
    
    // 调用订单更新接口
    jushuitanApiService.uploadOrder(orderDTO);
    log.info("聚水潭订单更新成功（标记退款商品）: orderNo={}", order.getOrderNo());
}
```

### 5.4 发货后退款 - 上传售后单

```java
private void uploadAftersaleToJushuitan(Order order, String refundNo) {
    // 查询退款记录和明细
    OrderRefund orderRefund = getRefundByRefundNo(refundNo);
    List<OrderRefundItem> refundItems = getRefundItemsByRefundNo(refundNo);
    List<OrderItem> orderItems = getOrderItems(order.getId());
    
    // 构建售后单数据
    JushuitanAftersaleDTO aftersaleDTO = new JushuitanAftersaleDTO();
    aftersaleDTO.setShopId(getShopIdFromConfig());
    aftersaleDTO.setOuterAsId(orderRefund.getRefundNo());
    aftersaleDTO.setSoId(order.getOrderNo());
    aftersaleDTO.setType("仅退款"); // 可根据实际情况判断是否为"普通退货"
    aftersaleDTO.setGoodStatus("BUYER_RECEIVED"); // 买家已收到货
    aftersaleDTO.setShopStatus("SUCCESS"); // 退款成功
    aftersaleDTO.setRefund(orderRefund.getRefundAmount());
    aftersaleDTO.setPayment(BigDecimal.ZERO);
    aftersaleDTO.setRemark(orderRefund.getRefundReason());
    
    // 构建商品明细
    Map<Long, OrderItem> orderItemMap = orderItems.stream()
        .collect(Collectors.toMap(OrderItem::getId, item -> item));
    
    List<JushuitanAftersaleDTO.Item> items = new ArrayList<>();
    for (OrderRefundItem refundItem : refundItems) {
        OrderItem orderItem = orderItemMap.get(refundItem.getOrderItemId());
        JushuitanAftersaleDTO.Item item = new JushuitanAftersaleDTO.Item();
        item.setOuterOiId(String.valueOf(orderItem.getId()));
        item.setSkuId(getSkuCode(orderItem));
        item.setQty(refundItem.getRefundQuantity());
        item.setAmount(refundItem.getRefundSubtotal());
        item.setType("退货"); // 或 "其它"
        items.add(item);
    }
    aftersaleDTO.setItems(items);
    
    // 调用售后单上传接口
    jushuitanApiService.uploadAftersale(aftersaleDTO);
    log.info("聚水潭售后单上传成功: orderNo={}, refundNo={}", order.getOrderNo(), refundNo);
}
```

## 六、数据库字段说明

- `order.erp_internal_order_id`：存储聚水潭返回的 `o_id`（内部订单号）
- 订单上传接口返回后已自动保存此字段
- 用于订单取消接口的参数

## 七、注意事项

1. 订单取消接口限制：
   - 仅支持特定状态的订单
   - 已发货订单无法取消，需使用售后单
2. 金额处理：
   - 订单更新时，`pay_amount` 和 `pay.amount` 保持原始金额
   - 退款金额通过商品明细的 `refund_qty` 体现
3. 数据一致性：
   - `outer_oi_id` 必须与订单上传时一致（使用 `OrderItem.id`）
   - 售后单的 `outer_as_id` 使用平台退款单号，需保证唯一
4. 错误处理：
   - 退款同步失败不应影响主退款流程
   - 记录详细日志，便于排查
   - 支持重试机制
5. 性能考虑：
   - 同步操作异步化或放在事务提交后
   - 避免影响退款响应时间
