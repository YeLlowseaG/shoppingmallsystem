## 1. 方案概述

### 1.1 背景

客户正在走商户申请流程，需要提前接入微信支付和支付宝支付功能。为了不影响开发进度，采用沙箱环境进行开发对接，等商户申请完成后，通过管理后台配置切换为生产环境。

### 1.2 目标

1. **提前接入**: 使用沙箱环境，不依赖商户申请流程
2. **灵活配置**: 通过管理后台配置支付参数，无需修改代码
3. **环境切换**: 支持沙箱/生产环境无缝切换
4. **全流程支持**: 覆盖预存款支付、订单支付、退款等全流程
5. **统一管理**: 管理后台可配置参数和开关控制

### 1.3 支付方式

- **微信支付**: 支持沙箱和生产环境
- **支付宝支付**: 支持沙箱和生产环境
- **预存款支付**: 现有功能保持不变
- **线下支付**: 现有功能保持不变

## 2. 需求分析

### 2.1 功能需求

#### 2.1.1 支付功能
- 订单支付（微信支付、支付宝支付）
- 预存款充值（微信支付、支付宝支付）
- 支付回调处理
- 支付状态查询

#### 2.1.2 退款功能
- 订单退款（支持部分退款和全额退款）
- 退款回调处理
- 退款状态查询

#### 2.1.3 配置管理
- 支付方式开关控制
- 沙箱/生产环境切换
- 支付参数配置（AppID、商户号、密钥等）
- 回调地址配置

### 2.2 非功能需求

- **安全性**: 敏感信息加密存储，回调验证签名
- **可靠性**: 支付和退款接口保证幂等性
- **可维护性**: 代码结构清晰，易于扩展
- **可配置性**: 所有参数可通过后台配置

### 3.2 设计模式

#### 3.2.1 策略模式
- 使用策略模式实现不同支付方式
- 每种支付方式独立实现，互不影响
- 便于扩展新的支付方式

#### 3.2.2 工厂模式
- 根据支付方式类型创建对应的支付策略实例
- 统一管理支付策略的创建

#### 3.2.3 配置模式
- 所有配置从 `SystemConfig` 表读取
- 支持动态配置，无需重启服务

### 3.3 环境隔离

- **沙箱环境**: 用于开发和测试，使用沙箱参数
- **生产环境**: 用于正式环境，使用生产参数
- **环境切换**: 通过配置项 `payment.xxx.env` 控制

     * 查询支付状态

## 6. 核心实现方案

### 6.1 支付流程

```
用户发起支付
    ↓
PaymentGatewayService.pay()
    ↓
根据支付方式选择策略
    ↓
PaymentStrategy.createPayment()
    ↓
调用第三方支付API
    ↓
返回支付URL/二维码
    ↓
用户完成支付
    ↓
第三方平台回调
    ↓
PaymentNotifyController接收回调
    ↓
验证签名
    ↓
更新支付记录和订单状态
```

### 6.2 退款流程

```
管理员发起退款
    ↓
RefundService.refund()
    ↓
根据支付方式选择策略
    ↓
PaymentStrategy.refund()
    ↓
调用第三方退款API
    ↓
第三方平台回调
    ↓
RefundNotifyController接收回调
    ↓
验证签名
    ↓
更新退款记录和订单状态
```

### 6.3 配置读取流程

```
PaymentConfigService.getWeChatPayConfig()
    ↓
从SystemConfig读取配置（带缓存）
    ↓
根据env判断使用沙箱还是生产配置
    ↓
构建配置对象
    ↓
返回配置
```

### 6.4 环境切换

1. 开发阶段：配置 `payment.xxx.env = sandbox`，使用沙箱参数
2. 商户申请完成后：在管理后台填写生产参数
3. 切换环境：修改 `payment.xxx.env = production`
4. 系统自动使用生产配置

## 10. 安全方案

### 10.1 敏感信息加密

#### 10.1.1 存储加密
- API密钥、私钥等敏感信息加密存储
- 使用AES加密算法
- 密钥存储在环境变量或配置中心

#### 10.1.2 传输加密
- 使用HTTPS传输
- 回调验证使用签名验证

### 10.2 回调验证

#### 10.2.1 微信支付回调验证
```java
// 验证签名
boolean verify = wechatPayUtil.verifySign(notifyData, signature);
if (!verify) {
    throw new PaymentException("签名验证失败");
}
```

#### 10.2.2 支付宝回调验证
```java
// 验证签名
boolean verify = alipayUtil.verifySign(notifyData, signature);
if (!verify) {
    throw new PaymentException("签名验证失败");
}
```

### 10.3 幂等性保证

#### 10.3.1 支付幂等性
- 使用订单号作为幂等键
- 重复支付请求返回相同结果
- 支付记录状态检查

#### 10.3.2 退款幂等性
- 使用退款单号作为幂等键
- 重复退款请求返回相同结果
- 退款记录状态检查

### 10.4 日志记录

- 记录所有支付和退款操作
- 记录回调处理过程
- 记录异常情况
- 敏感信息脱敏记录

## 12. 注意事项

### 12.1 开发注意事项

1. **证书管理**
   - 证书文件存储在安全目录
   - 生产环境证书不要提交到代码仓库
   - 证书文件权限控制

2. **配置管理**
   - 敏感配置不要硬编码
   - 使用配置中心或环境变量
   - 配置变更需要验证

3. **异常处理**
   - 网络异常处理
   - 超时处理
   - 第三方服务异常处理

4. **日志记录**
   - 记录关键操作日志
   - 敏感信息脱敏
   - 日志级别控制

### 12.2 部署注意事项

1. **环境变量**
   - 生产环境使用环境变量存储敏感信息
   - 不要将敏感信息写入配置文件

2. **证书部署**
   - 证书文件部署到安全目录
   - 设置正确的文件权限
   - 定期更新证书

3. **回调地址**
   - 确保回调地址可访问
   - 使用HTTPS协议
   - 配置防火墙规则

### 12.3 运维注意事项

1. **监控告警**
   - 监控支付成功率
   - 监控回调处理
   - 设置异常告警

2. **数据备份**
   - 定期备份支付记录
   - 备份配置信息

3. **应急预案**
   - 支付异常处理流程
   - 退款异常处理流程
   - 服务降级方案

### 12.4 安全注意事项

1. **签名验证**
   - 所有回调必须验证签名
   - 签名验证失败拒绝处理

2. **参数校验**
   - 严格校验支付参数
   - 防止参数注入攻击
