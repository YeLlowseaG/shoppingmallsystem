# 聚水潭开放平台售后单上传接口文档

## 接口概述
**接口名称**：售后上传
**接口地址**：
- **正式环境**：`https://openapi.jushuitan.com/open/aftersale/upload`
- **测试环境**：`https://dev-api.jushuitan.com/open/aftersale/upload`

**核心功能**：用于向ERP系统上传或更新售后单信息。
**重要限制**：**从其他平台下载到ERP的售后单，不可以通过此接口修改。**

## 关键业务流程说明

### 售后单状态流转
- **普通退货/仅退款**：买家发起 → 生成售后单（待确认）→ 卖家同意退款 → (买家发货/卖家收货) → 处理退款 → 已确定
- **换货申请**：买家发起 → 生成售后单（待确认）→ 卖家同意换货 → 买家退货 → 卖家收货 → 卖家处理换货 → 买家收到货 → 已确认
- **补发申请**：买家发起 → 生成售后单（待确认）→ 卖家同意补发 → 卖家处理补发 → 买家收到货 → 已确认
- **售后单作废**：在“待确认”状态下，买家取消申请，售后单将变为“作废”状态。**作废状态的售后单上传修改无效。**

### 对订单状态的影响
**售后上传不会直接改变订单状态**，但会为订单打上标签：
- 发货前上传售后 → 订单打上“发货前售后”标签。
- 发货后上传售后 → 订单打上“发货后售后”标签。
- 前后都上传 → 同时打上两个标签。

### 自有商城拦截发货指引
若希望通过售后单在发货前拦截商品，可参考以下方式：
1.  **部分退款**：先上传“仅退款”类型售后单，确认后，在调用“订单上传接口”时，于`items`节点将`refund_status`设为`success`，发货时可拦截对应商品。
2.  **整单退款**：建议直接调用“订单取消接口”。
3.  **无售后单拦截**：发货前订单若不希望传输售后单，可直接通过“订单上传接口”的`items`节点中的`refund_status`字段拦截。

## 公共请求参数
所有请求必须包含以下公共参数：

| 参数名 | 类型 | 是否必填 | 描述 |
| :--- | :--- | :--- | :--- |
| `app_key` | String | 是 | POP平台分配给应用的唯一标识。 |
| `access_token` | String | 是 | 通过授权码获取的访问令牌。 |
| `timestamp` | Long | 是 | UNIX时间戳（秒），与服务器时间差需在10分钟内。 |
| `charset` | String | 是 | 字符编码，固定值：`utf-8`。 |
| `version` | String | 是 | API版本号，固定值：`2`。 |
| `sign` | String | 是 | 数字签名。 |

## 业务请求参数
请求体为**JSON数组**，数组中每个对象表示一个售后单。主要参数如下：

| 参数名 | 类型 | 是否必填 | 示例值 | 描述 |
| :--- | :--- | :--- | :--- | :--- |
| `shop_id` | integer | **是** | `10206764` | 店铺编号。 |
| `outer_as_id` | string | **是** | `331805` | **平台唯一售后单号**。 |
| `so_id` | string | **是** | `21120211072883513540` | **平台订单号**（对应订单页面的线上单号）。 |
| `type` | string | **是** | `其它` | **售后类型**。可选值：`普通退货`，`其它`，`拒收退货`，`仅退款`，`投诉`，`补发`，`维修`，`换货`。 |
| `good_status` | string | **是** | `BUYER_RETURNED_GOODS` | **货物状态**。可选值：`BUYER_NOT_RECEIVED`（买家未收到货），`BUYER_RECEIVED`（买家已收到货），`BUYER_RETURNED_GOODS`（买家已退货），`SELLER_RECEIVED`（卖家已收到退货）。**可更新**。 |
| `question_type` | string | **是** | | 问题类型。**可更新**。 |
| `refund` | number | **是** | `0` | **卖家应退金额**。 |
| `payment` | number | **是** | `0` | **买家应补偿金额**。 |
| `items` | array | **是** | | **售后商品明细列表**。 |
| `shop_status` | string | 否 | `wait` | **平台单据状态**。可选值：`WAIT_SELLER_AGREE`（买家申请，待卖家同意），`WAIT_BUYER_RETURN_GOODS`（卖家同意，待买家退货），`WAIT_SELLER_CONFIRM_GOODS`（买家已退货，待卖家收货），`SELLER_REFUSE_BUYER`（卖家拒绝售后），`WAIT_SELLER_DELIVER_GOODS`（等待卖家发货），`REISSUE_SELLER_DELIVERY`（补发卖家发货），`CLOSED`（售后关闭，待确认时传入此状态ERP售后单将自动作废），`SUCCESS`（退款成功）。**可更新**。<br>**特别注意**：对于抖音、拼多多、淘系等平台的换货单，若通过接口将状态改为`SUCCESS`但发出的快递单号为空，平台可能判定为超时未处理并强制退款，线上售后类型会变为`普通退货`。 |
| `logistics_company` | string | 否 | | 快递公司。**可更新**（货物状态为`SELLER_RECEIVED`后不可更新）。 |
| `l_id` | string | 否 | | 物流单号。**如果传入的物流单号系统中已存在于其他售后单，则不会新建，直接匹配到原单并返回原单号**。**可更新**（货物状态为`SELLER_RECEIVED`后不可更新）。 |
| `total_amount` | number | 否 | `0` | 原订单总金额。 |
| `warehouse_type` | number | 否 | `2` | **仓库类型**。主仓=`1`， 销退仓=`2`， 进货仓=`3`， 次品仓=`4`， 自定义1仓=`6`， 自定义2仓=`7`， 自定义3仓=`8`（只能选择已启用的仓）。 |
| `wms_co_id` | number | 否 | | 收货仓编码。 |
| `receiver_state`/`city`/`district`/`address`| string | 条件必填 | | 收货人省/市/区/详细地址。**如果要传收件信息，这些字段必传**，否则ERP上展示为空。 |
| `send_lc_id` | string | 否 | | 寄出快递编码（用于换货、补发时卖家发货）。 |
| `send_lc_name` | string | 否 | | 寄出快递名称。 |

| `freight` | number | 否 | | 卖家应退运费。 |

### `items` 售后商品明细字段说明

| 字段名 | 类型 | 是否必填 | 示例值 | 描述 |
| :--- | :--- | :--- | :--- | :--- |
| `sku_id` | string | **是** | `sn2` | 商家商品编码（规格ID）。 |
| `qty` | integer | **是** | `2` | **退货/换货/补发数量**。 |
| `amount` | number | **是** | `34.45` | **该SKU的退款金额**。 |
| `type` | string | **是** | `退货` | **明细类型**。可选值：`退货`，`换货`，`其它`，`补发`。**注意**：若为`换货`类型的售后单，`items`节点需传两条明细，一条`type`为`"退货"`，一条`type`为`"换货"`。 |
| `outer_oi_id` | string | 条件必填 | | **平台订单明细编号**。存在则会按此作为唯一性判断。<br>1. **开启售后单下载拦截订单功能时，若不传此字段会导致整单退款，订单转为取消**。<br>2. 订单包含组合装商品时**必传**。<br>3. 若传入此字段，则`name`、`pic`、`properties_value`可不填。 |
| `name` | string | 否 | | 商品名称。 |
| `pic` | string | 否 | | 商品图片地址。 |
| `properties_value` | string | 否 | | 商品属性规格。 |
| `des` | string | 否 | | 商品备注。 |

## 返回参数说明
接口返回统一的JSON格式数据：

| 参数名 | 类型 | 示例值 | 说明 |
| :--- | :--- | :--- | :--- |
| `code` | integer | `0` | **错误码**，`0`表示成功。 |
| `msg` | string | `""` | **错误描述**信息。 |
| `data` | object | `{}` | 业务数据对象。 |
| `data.datas` | array | `[]` | 各售后单处理结果的数组。 |
| `data.datas[].issuccess` | boolean | `true` | **该售后单处理是否成功**。 |
| `data.datas[].msg` | string | `""` | **该售后单处理结果的详细描述**。 |
| `data.datas[].as_id` | integer | `0` | 系统生成的**内部售后单号**。 |
| `data.datas[].outer_as_id` | string | `""` | 对应的**外部售后单号**（即请求传入的`outer_as_id`）。 |
| `data.datas[].so_id` | string | `""` | 对应的**线上订单号**（即请求传入的`so_id`）。 |
| `data.datas[].o_id` | integer | `0` | 对应的**内部订单号**。 |

## 错误码与排查方法

| 现象/错误码 | 错误信息示例 | 排查方法 |
| :--- | :--- | :--- |
| **参数校验错误** | `"平台售后单号:12343567;线上单号1111111111111不存在退回类型的商品，请验证数据规范性！"` | 1. 检查`items`节点里的`type`是否必填且正确。<br>2. **换货单**：检查`items`是否包含一退一换两条明细。<br>3. **非换货单**：检查`items`的`type`值是否在（`退货`，`换货`，`其它`，`补发`）范围内，**注意“其它”不要写成“其他”**。 |
| **数据不存在错误** | `"System.Exception: 找不到相应的订单[202210270944]"` | 检查系统中是否存在该`so_id`对应的订单。 |
| **通用错误** | `"验证失败!无效签名"` (code=120) | 检查签名(`sign`)计算方式是否正确。 |
