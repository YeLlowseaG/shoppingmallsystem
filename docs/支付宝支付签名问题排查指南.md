# 支付宝支付签名问题排查指南

## 问题描述

支付宝支付时出现 `invalid-signature` 错误，提示验签失败。

## 常见错误信息

1. **错误代码**：`invalid-signature`
2. **错误原因**：
   - `验签出错，建议检查签名字符串或签名私钥与应用公钥是否匹配`
   - `请确认charset参数放在了URL查询字符串中且各参数值使用charset参数指示的字符集编码`

## 问题根源分析

### 问题1：charset参数处理错误

**错误做法**：
- 将 `charset` 参数只放在表单参数中，不放在URL中
- 或者将 `charset` 参数只放在URL中，不参与签名

**正确做法**：
- `charset` 参数必须**同时**满足两个条件：
  1. 放在URL查询字符串中（如：`gateway.do?charset=utf-8`）
  2. 参与签名（支付宝验签时会从URL中读取并包含在验签字符串中）

**原因**：
- 支付宝的验签字符串格式：`...&charset=utf-8&...`
- 说明支付宝在验签时会包含 `charset` 参数
- 如果签名时不包含 `charset`，会导致签名不匹配

### 问题2：参数值URL编码错误

**错误做法**：
- 签名时对参数值进行URL编码（如：`timestamp=2025-12-26+15%3A57%3A58`）

**正确做法**：
- 签名时使用**原始值**，不进行URL编码（如：`timestamp=2025-12-26 15:57:58`）

**原因**：
- 支付宝的验签字符串中的参数值都是**未编码的原始值**
- 例如：`timestamp=2025-12-26 15:57:58`（空格和冒号都是原始字符）
- 如果签名时使用编码后的值，会导致签名不匹配

**注意**：
- 表单提交时，浏览器会自动对表单参数进行URL编码
- 支付宝接收到编码后的值，但在验签前会先解码
- 验签时使用的是解码后的原始值

## 正确的签名流程

### 1. 构建签名参数

```java
Map<String, String> params = new HashMap<>();
params.put("app_id", config.getAppid());
params.put("method", "alipay.trade.page.pay");
params.put("charset", "utf-8");  // 必须包含在签名参数中
params.put("sign_type", "RSA2");
params.put("timestamp", formatTimestamp(new Date()));  // 格式：yyyy-MM-dd HH:mm:ss
params.put("version", "1.0");
params.put("notify_url", cleanNotifyUrl);
params.put("biz_content", mapToJson(bizContent));
```

### 2. 生成待签名字符串

```java
private static String getSignContent(Map<String, String> params) {
    // 1. 参数排序（按字典序）
    List<String> keys = new ArrayList<>(params.keySet());
    Collections.sort(keys);
    
    // 2. 拼接字符串（使用原始值，不进行URL编码）
    StringBuilder sb = new StringBuilder();
    for (String key : keys) {
        String value = params.get(key);
        // 跳过sign参数和空值
        if ("sign".equals(key) || value == null || value.isEmpty()) {
            continue;
        }
        if (sb.length() > 0) {
            sb.append("&");
        }
        // 直接使用原始值，不进行URL编码
        sb.append(key).append("=").append(value);
    }
    return sb.toString();
}
```

**关键点**：
- ✅ 参数按字典序排序
- ✅ 跳过 `sign` 参数和空值
- ✅ **使用原始值，不进行URL编码**
- ✅ 包含 `charset` 参数

### 3. RSA2签名

```java
private static String sign(String content, String privateKey) {
    // 1. 处理私钥格式
    String privateKeyPEM = privateKey
            .replace("-----BEGIN PRIVATE KEY-----", "")
            .replace("-----END PRIVATE KEY-----", "")
            .replace("-----BEGIN RSA PRIVATE KEY-----", "")
            .replace("-----END RSA PRIVATE KEY-----", "")
            .replaceAll("\\s", "");
    
    // 2. Base64解码
    byte[] keyBytes = Base64.getDecoder().decode(privateKeyPEM);
    PKCS8EncodedKeySpec keySpec = new PKCS8EncodedKeySpec(keyBytes);
    KeyFactory keyFactory = KeyFactory.getInstance("RSA");
    PrivateKey key = keyFactory.generatePrivate(keySpec);
    
    // 3. SHA256withRSA签名
    Signature signature = Signature.getInstance("SHA256withRSA");
    signature.initSign(key);
    signature.update(content.getBytes(StandardCharsets.UTF_8));
    byte[] signBytes = signature.sign();
    
    // 4. Base64编码
    return Base64.getEncoder().encodeToString(signBytes);
}
```

### 4. 构建支付表单

```java
private static String buildFormHtmlWithCharset(String gateway, Map<String, String> params) {
    StringBuilder html = new StringBuilder();
    String cleanGateway = gateway.replace("`", "");
    
    // charset放在URL查询字符串中
    String formAction = cleanGateway + (cleanGateway.contains("?") ? "&" : "?") + "charset=utf-8";
    
    html.append("<form id='alipayForm' method='post' action='").append(escapeHtml(formAction)).append("'>");
    
    // 表单参数（包含charset，浏览器提交时会自动URL编码）
    for (Map.Entry<String, String> entry : params.entrySet()) {
        String cleanKey = entry.getKey().replace("`", "");
        String cleanValue = entry.getValue().replace("`", "");
        html.append("<input type='hidden' name='").append(escapeHtml(cleanKey))
                .append("' value='").append(escapeHtml(cleanValue)).append("'/>");
    }
    
    html.append("</form>");
    html.append("<script>document.getElementById('alipayForm').submit();</script>");
    return html.toString();
}
```

**关键点**：
- ✅ `charset` 放在URL查询字符串中（`gateway.do?charset=utf-8`）
- ✅ 表单参数中包含所有参数（包括 `charset`）
- ✅ 使用 `escapeHtml` 转义HTML特殊字符
- ✅ 浏览器提交时会自动对表单参数进行URL编码

## 常见错误示例

### 错误1：charset不参与签名

```java
// ❌ 错误：charset不参与签名
params.put("charset", "utf-8");  // 只放在URL中，不参与签名
```

**结果**：签名不匹配，因为支付宝验签时会包含 `charset`

### 错误2：参数值URL编码

```java
// ❌ 错误：对参数值进行URL编码
String encodedValue = URLEncoder.encode(value, "UTF-8");
sb.append(key).append("=").append(encodedValue);
// 结果：timestamp=2025-12-26+15%3A57%3A58
```

**结果**：签名不匹配，因为支付宝验签时使用原始值（`timestamp=2025-12-26 15:57:58`）

### 错误3：时间戳格式错误

```java
// ❌ 错误：时间戳格式不正确
params.put("timestamp", new Date().toString());  // 格式不符合要求
```

**正确格式**：`yyyy-MM-dd HH:mm:ss`（如：`2025-12-26 15:57:58`）


### 2. 对比支付宝验签字符串

支付宝错误信息中会提供验签字符串，对比：
- 参数顺序是否一致（字典序）
- 参数值是否一致（原始值，未编码）
- 是否包含所有必需参数（包括 `charset`）

### 3. 检查私钥和公钥

- 确保应用私钥和支付宝公钥匹配
- 确保私钥格式正确（PKCS#8格式）
- 确保私钥包含完整的头部和尾部

## 检查清单

在修复签名问题时，按以下清单检查：

- [ ] `charset` 参数是否包含在签名参数中？
- [ ] `charset` 参数是否放在URL查询字符串中？
- [ ] 签名时是否使用原始值（未URL编码）？
- [ ] 参数是否按字典序排序？
- [ ] 是否跳过了 `sign` 参数和空值？
- [ ] 时间戳格式是否为 `yyyy-MM-dd HH:mm:ss`？
- [ ] 私钥和公钥是否匹配？
- [ ] 签名算法是否为 `SHA256withRSA`（RSA2）？
