# 预存款支付状态流转说明

## 状态定义

创建了 `DepositStatus` 常量类，统一管理预存款状态：

| 状态值 | 常量名 | 说明 | 适用场景 |
|--------|--------|------|----------|
| 0 | `PENDING_AUDIT` | 待审核 | 线下充值、代充值等需要管理员审核的场景 |
| 1 | `APPROVED` | 已通过 | 支付成功或审核通过 |
| 2 | `REJECTED` | 已拒绝 | 支付失败或审核拒绝 |
| 3 | `PAYING` | 支付中 | 在线充值（支付宝、微信等），用户已发起支付，等待支付完成 |
| 4 | `TIMEOUT` | 已超时 | 支付超时未完成 |

## 支付状态流转

### 在线充值（支付宝/微信）

```
创建充值记录 → 支付中(3) → 支付成功回调 → 已通过(1)
                              ↓
                        支付失败回调 → 已拒绝(2)
                              ↓
                        支付超时 → 已超时(4)
```

**详细流程：**

1. **创建充值记录**
   - 用户发起充值请求
   - 创建 `PreDepositDetail` 记录
   - 状态设为 `PAYING` (3) - 支付中
   - 不更新余额，等待支付回调确认

2. **支付成功回调**
   - 支付宝/微信服务器调用回调接口
   - 验证签名和订单号
   - 状态更新为 `APPROVED` (1) - 已通过
   - 更新预存款余额
   - 记录外部交易号和审核时间

3. **支付失败回调**
   - 支付失败或用户取消支付
   - 状态更新为 `REJECTED` (2) - 已拒绝
   - 不更新余额

4. **支付超时**（可选，需要定时任务）
   - 如果超过一定时间（如30分钟）仍未收到回调
   - 状态更新为 `TIMEOUT` (4) - 已超时
   - 不更新余额

### 线下充值/代充值

```
创建充值记录 → 待审核(0) → 管理员审核通过 → 已通过(1)
                              ↓
                        管理员审核拒绝 → 已拒绝(2)
```

**详细流程：**

1. **创建充值记录**
   - 用户上传支付凭证或管理员代充值
   - 创建 `PreDepositDetail` 记录
   - 状态设为 `PENDING_AUDIT` (0) - 待审核
   - 不更新余额，等待管理员审核

2. **管理员审核通过**
   - 管理员审核支付凭证
   - 状态更新为 `APPROVED` (1) - 已通过
   - 更新预存款余额
   - 记录审核时间

3. **管理员审核拒绝**
   - 管理员拒绝充值申请
   - 状态更新为 `REJECTED` (2) - 已拒绝
   - 不更新余额

## 状态显示

前端和管理后台的状态显示已经支持所有状态：

- **待审核** (0)：橙色标签
- **已通过** (1)：绿色标签
- **已拒绝** (2)：红色标签
- **支付中** (3)：蓝色标签
- **已超时** (4)：灰色标签

## 注意事项

1. **状态流转的原子性**：状态更新和余额更新必须在同一个事务中完成
2. **防止重复回调**：已通过状态的记录需要检查外部交易号是否一致
3. **状态检查**：只有"支付中"状态的记录才能处理支付回调
4. **超时处理**：建议添加定时任务，定期检查"支付中"状态的记录，超过一定时间后更新为"已超时"

## 与支付宝/微信对接的最佳实践

1. **创建订单时**：状态设为"支付中"，表示用户已发起支付
2. **支付回调时**：
   - 验证签名和订单号
   - 检查状态是否为"支付中"
   - 更新状态和余额
   - 返回正确的响应（支付宝需要返回"success"）
3. **同步回调（return_url）**：
   - 验证签名
   - 处理业务逻辑（如果异步回调未处理）
   - 重定向到前端页面
4. **异步回调（notify_url）**：
   - 验证签名
   - 处理业务逻辑
   - 返回"success"（支付宝）或特定格式（微信）

## 测试建议

1. **测试支付成功流程**：
   - 创建充值记录 → 状态应为"支付中"
   - 完成支付 → 状态应更新为"已通过"，余额应增加

2. **测试支付失败流程**：
   - 创建充值记录 → 状态应为"支付中"
   - 支付失败 → 状态应更新为"已拒绝"，余额不变

3. **测试重复回调**：
   - 支付成功后多次收到回调 → 应正确处理重复回调，不重复更新余额

4. **测试状态检查**：
   - 非"支付中"状态的记录收到回调 → 应拒绝处理并记录警告日志
